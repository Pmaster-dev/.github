# 🌿 MBTQ Ecosystem Detailed Branch Naming & Workflow Standards
# Target Maintainer: @pinkycollie
# Created: 2026-08-09
# Status: COMPLETED

This document defines the official, standardized branch naming taxonomy and workflow conventions across all MBTQ / 360Magicians ecosystem repositories. It classifies branches by category (Services, APIs, Bots, Compute/Infra, Documentation, GitHub Actions, and Human/Developer contributions) to maintain precision during automated rebuilds and PMaster pipeline execution.

---

## 1. Branch Naming Taxonomy Overview

Branches should follow the structured format:
`<category>/<scope>/<short-description>`

Where:
* `<category>`: The explicit category prefix (e.g. `service`, `api`, `bot`, `compute`, `docs`, `github`, `human`, `feature`, `fix`).
* `<scope>`: The specific service, module, or subsystem target (e.g. `deafauth`, `pinksync`, `360magicians`, `gke`, `terraform`).
* `<short-description>`: Brief kebab-case description of the change.

---

## 2. Category-Specific Branch Conventions

### **1. Services (`service/`)**
Used for core microservices and backend runtime updates.
* `service/api:in/deafauth-auth-route`
* `service/pinksync/accessibility-transformer`
* `service/360magicians/multi-domain-vertex`
* `service/mbtquniverse/staking-showcase`

### **2. APIs & Endpoints (`api/`)**
Used for OpenAPI schemas, WebSocket room protocols, and REST route specifications.
* `api/deafauth/v1-openapi-spec`
* `api/pinksync/websocket-rooms`
* `api/magicians/gemini-studio-proxy`

### **3. Automated Bots & AI Agents (`bot/` & `agent/`)**
Used for automated PRs generated by bots (Dependabot, Renovate, Triage Bot) or AI Agents (Developer Magicians, PMaster, Copilot).
* `bot/dependabot/npm-audit-fix`
* `bot/renovate/gcp-sdk-update`
* `agent/pmaster/ecosystem-sync`
* `agent/quinn/fibonrose-validator`

### **4. Compute & Infrastructure (`compute/` & `infra/`)**
Used for Terraform scripts, GCP Kubernetes GKE manifests, Cloud Run containers, and Docker Compose configurations.
* `compute/gke/node-pool-scaling`
* `compute/cloudrun/pinkflow-firecracker-sandbox`
* `infra/terraform/firestore-native-setup`
* `infra/nginx/ssl-ingress-config`

### **5. Documentation (`docs/` & `ddoc/`)**
Used for architecture updates, API guides, Obsidian/Drive exports, and README files.
* `docs/architecture/master-audit-v1`
* `docs/obsidian/vault-export-sync`
* `ddoc/deafauth/prompt-mechanics-guide`

### **6. GitHub Actions & Workflows (`github/` & `workflow/`)**
Used for GitHub Actions pipelines, starter workflow updates, and GHES branch sync scripts.
* `github/workflows/centralized-ecosystem-sync`
* `github/actions/validate-data-schema`
* `workflow/sync-ghes/v4-artifact-downgrade`

### **7. Human Developers & Maintainers (`human/` & `@username/`)**
Used for human maintainers (@pinkycollie) making explicit manual commits or architectural additions.
* `human/pinkycollie/sovereign-build-refactor`
* `human/pinkycollie/sign-visual-system-theme`
* `pinkycollie/feature/web3-wallet-connector`

## 3. Base Main Branch & Merging Strategy

1. **Base Main Branch (`main`)**:
   * The canonical, production-ready branch in every repository.
   * Direct execution on `main` is prohibited by repository runtime rules (`fail_closed: true`).
2. **Feature & Service Branches**:
   * Created off `main` using the taxonomy above (e.g. `service/api:in/deafauth-profiles`).
3. **Merging Protocol**:
   * Requires Fibonrose Task Validator checkpoint confirmations.
   * Requires `script/validate-data` or PyYAML test passes before merging into `main`.
